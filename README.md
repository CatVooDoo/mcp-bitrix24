# Bitrix24 CRest MCP Server & Webhook Gateway для OpenClaw

Легковесный, высокопроизводительный шлюз и MCP-сервер (Model Context Protocol) на **PHP 8.1+** с официальной библиотекой **[CRest](https://github.com/bitrix-tools/crest)** для интеграции ИИ-агента **OpenClaw (DeepSeek V4.1 Flash)** с порталом **Битрикс24**.

Архитектура проекта спроектирована с четким разделением на этапы развития:
* **Этап 1 (Текущий — Агент Чата / L1 Support):** Полное управление диалогами в чатах и Открытых линиях со **строгим Read-Only доступом** к CRM (Лиды, Сделки, Компании, Контакты, Смарт-процесс «ДОГОВОРЫ») и Задачам (включая чтение комментариев, результатов и встроенного чата задачи).
* **Этап 2 (Заложен в архитектуру — ПМ-Агент):** Создание и маршрутизация задач, контроль дедлайнов, пинг исполнителей и управление воронками (`src/Mcp/PmAgentTools.php`, отключен по умолчанию флагом `B24_ENABLE_PM_AGENT_TOOLS = false`).

---

## 1. Архитектурные правила и принципы безопасности

1. **Неизменность ядра `CRest`:** Файл `CRest.php` (`crest.php`) используется «как есть» из официального репозитория `bitrix-tools/crest` и **не модифицируется**. Сохранена регистронезависимая совместимость для Linux/Ubuntu.
2. **Правило `settings.php`:** Исходные строки `settings.php` остаются нетронутыми. Все параметры конфигурируются через добавление констант `define(...)` с проверками `if (!defined(...))` и поддержкой переменных окружения `getenv()`.
3. **Точка входа вебхуков чата:** Приемник исходящих событий от Битрикс24 располагается строго в файле `chatWeebhook.php` (с двумя буквами `e`).
4. **Безопасность данных (Guardrails):** На уровне MCP-сервера в Фазе 1 полностью отсутствуют методы на запись/изменение CRM и задач. Агент физически не способен случайно удалить сделку, закрыть задачу или изменить договор.
5. **Чистота STDOUT для MCP:** Отключен любой вывод PHP ошибок и предупреждений в стандартный поток (`display_errors = 0`), логи ведутся в формате JSON в директорию `logs/`.

## 3. Необходимые права (Scopes) Входящего вебхука в Битрикс24

В Битрикс24 перейдите в раздел **Разработчикам → Другое → Входящий вебхук**, создайте вебхук и отметьте следующие разрешения:
* `crm` — чтение Лидов, Сделок, Контактов, Компаний и Смарт-процесса «ДОГОВОРЫ».
* `task` и `tasks_extended` — чтение карточек задач, чеклистов, результатов и комментариев.
* `im` — чтение сообщений чатов, чатов задач и отправка сообщений.
* `imbot` — ответы в чат от имени бота, отправка индикатора набора текста (typing).
* `imopenlines` — управление сессиями Открытых линий и перевод на живого оператора.
* `user` — чтение ФИО и контактов ответственных сотрудников.
* `sonet_group` — получение названий рабочих групп и проектов.
* `disk` — доступ к метаданным вложений и файлов.

Скопируйте URL вебхука (вида `https://your-domain.bitrix24.ru/rest/1/webhook_token/`).

## 4. Конфигурация `settings.php`

Все настройки шлюза и MCP могут быть заданы как константами в `settings.php`, так и переменными окружения:

```php
// --- Стандартные константы CRest ---
define('C_REST_WEB_HOOK_URL', 'https://your-domain.bitrix24.ru/rest/1/your_secret_webhook/');
define('C_REST_BLOCK_LOG', true); // Отключение дампа в stdout для чистоты MCP
define('C_REST_LOGS_DIR', __DIR__ . '/logs/crest/');

// --- Дополнительные константы шлюза OpenClaw и MCP ---
define('B24_OUTGOING_WEBHOOK_TOKEN', 'токен_исходящего_вебхука'); // Проверка auth.application_token
define('B24_BOT_ID', 0); // ID чат-бота (0 = отправка от имени пользователя вебхука через im.message.add)
define('B24_BOT_CLIENT_ID', '');
define('B24_CONTRACTS_ENTITY_TYPE_ID', 0); // 0 = автоматическое определение смарт-процесса "ДОГОВОРЫ"
define('B24_PUBLIC_COMMENT_PREFIX', ''); // Префикс публичных комментариев (например, '[Публично]')

// Настройки связи с OpenClaw (DeepSeek V4.1 Flash)
define('OPENCLAW_GATEWAY_URL', 'http://127.0.0.1:19001/hooks/agent');
define('OPENCLAW_HOOK_TOKEN', 'ваш_токен_openclaw_шлюза');
define('MCP_HTTP_AUTH_TOKEN', 'секретный_токен_для_http_mcp');

// Антидребезг (секунды, 0 = выключен)
define('B24_DEBOUNCE_SECONDS', 0);

// Архитектурный флаг Этапа 2 (ПМ-агент)
define('B24_ENABLE_PM_AGENT_TOOLS', false);
```

## 5. Доступные MCP Инструменты

MCP-сервер предоставляет **15 строго типизированных инструментов** со спецификацией `inputSchema`:

1. **`b24_get_client_dossier`** — Молниеносный сбор досье клиента за один пакетный запрос `CRest::callBatch`: Контакт, Компания, активные Сделки, Договоры и последние 10 Задач. Аргументы: `contact_id`, `company_id`, `lead_id`, `deal_id`, `chat_id`.
2. **`b24_search_crm_by_comm`** — Поиск сущностей CRM по номеру телефона или адресу email (`crm.duplicate.findbycomm`).
3. **`b24_get_leads`** — Поиск и получение Лидов (`lead_id` или фильтры `company_id`, `contact_id`, `status_id`, `search_query`).
4. **`b24_get_deals`** — Поиск и получение Сделок (`deal_id` или фильтры `company_id`, `contact_id`, `stage_id`, `category_id`, `search_query`).
5. **`b24_get_companies`** — Получение Компаний со всеми пользовательскими полями `UF_CRM_*`.
6. **`b24_get_contacts`** — Получение Контактов (`contact_id`, `company_id` или умный пакетный поиск по ФИО).
7. **`b24_get_contracts`** — Чтение Смарт-процесса «ДОГОВОРЫ» (`crm.item.list` / `crm.item.get` с `camelCase` полями).
8. **`b24_get_tasks`** — Список задач с фильтрацией по CRM (`UF_CRM_TASK` префиксы `C_`, `CO_`, `D_`, `L_`), ответственному, группе или статусу.
9. **`b24_get_task_and_chat_details`** — Исчерпывающие данные по задаче: карточка, чек-лист (`task.checklistitem.getlist`), результаты (`tasks.task.result.list`), комментарии (`task.commentitem.getlist`) и сообщения встроенного чата задачи (`im.dialog.messages.get`).
10. **`b24_get_chat_history`** — Чтение истории сообщений чата или Открытой линии (`dialog_id`, `limit`).
11. **`b24_chat_action`** — Выполнение действий в диалоге: `reply` (отправка ответа), `typing` (индикатор набора), `transfer_to_operator` (перевод на человека с передачей внутренней системной сводки).
12. **`b24_poll_openlines`** — Опрос активных сессий Открытых линий и чатов для выявления новых и неотвеченных сообщений клиентов с маркерами статуса (`[STATUS: NEED_REPLY]`) и срочности (`[PRIORITY: URGENT]`).
13. **`b24_create_task`** — Постановка новой задачи в Битрикс24 по регламенту компании из 6 пунктов (автоформат названия `<Группа> | <Смысл> <DD.MM.YYYY>`, план действий, участники, дедлайн, проектная группа, чекбокс учета времени и трудозатраты) с поддержкой добавления чек-листа (`checklist`).
14. **`b24_get_workgroups`** — Поиск и получение списка проектных рабочих групп (`sonet_group.get`) для выбора `group_id` при постановке задачи.
15. **`b24_add_task_checklist`** — Добавление чек-листа в задачу Битрикс24 (`task.checklistitem.add`) через пакетный запрос `CRest::callBatch`. Аргументы: `task_id` (ID задачи), `items` (массив строк пунктов чек-листа).

## 6. Настройка Nginx и PHP-FPM на Ubuntu Server

В конфигурацию сайта Nginx добавьте:

```nginx
server {
    listen 80;
    server_name b24-mcp.your-domain.com;
    root /var/www/html;
    index index.php;

    client_max_body_size 64M;

    # Точка входа исходящих вебхуков Битрикс24
    location = /chatWeebhook.php {
        fastcgi_pass unix:/var/run/php/php8.4-fpm.sock; # или php:9000 в docker
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_read_timeout 120;
        include fastcgi_params;
    }

    # HTTP-режим MCP-сервера
    location = /mcp_server.php {
        fastcgi_pass unix:/var/run/php/php8.4-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_read_timeout 300;
        include fastcgi_params;
    }

    location ~ \.php$ {
        fastcgi_pass unix:/var/run/php/php8.4-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;
    }

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }
}
```

## 7. Подключение к OpenClaw (DeepSeek V4.1 Flash)

### Вариант А: Локальный запуск через CLI STDIO

Если агент OpenClaw и сервер Битрикс24 расположены на одном сервере, настройте вызов команды в конфигурации OpenClaw:

```json
{
  "mcpServers": {
    "bitrix24": {
      "command": "php",
      "args": ["/var/www/html/mcp_server.php"],
      "env": {
        "C_REST_WEB_HOOK_URL": "https://your-domain.bitrix24.ru/rest/1/webhook_token/"
      }
    }
  }
}
```

### Вариант Б: Удаленное подключение через HTTP JSON-RPC 2.0

Если агент подключается по сети:

```json
{
  "mcpServers": {
    "bitrix24": {
      "url": "https://b24-mcp.your-domain.com/mcp_server.php",
      "headers": {
        "Authorization": "Bearer секретный_токен_для_http_mcp"
      }
    }
  }
}
```

### Подключение исходящих вебхуков Битрикс24

В Битрикс24 перейдите в **Разработчикам → Другое → Исходящий вебхук**:
* **URL обработчика:** `https://b24-mcp.your-domain.com/chatWeebhook.php`
* **События:** `ONIMBOTMESSAGEADD`, `ONIMMESSAGEADD`, `ONIMCOMMANDADD`.
* Скопируйте `Код авторизации (токен)` и пропишите его в `B24_OUTGOING_WEBHOOK_TOKEN` в `settings.php`.

Благодаря использованию `fastcgi_finish_request()`, вебхук мгновенно отвечает кодом `200 OK`, собирает досье клиента и асинхронно передает задачу в OpenClaw Gateway.

## 8. Автоматический опрос Открытых линий (Cron & Автоматизация OpenClaw)

Для порталов, где не настроены исходящие вебхуки, или в качестве резервного мониторинга входящих обращений, в проект включен инструмент периодического опроса: скрипт `poll_openlines.php` и сервис `src/Services/OpenLinesPoller.php`.

### Назначение и возможности
1. **Автоматический поллинг:** Периодический опрос последних диалогов и сессий Открытых линий через `im.recent.get`.
2. **Умная разметка маркерами:** Автоматический анализ последнего сообщения, автора, времени ожидания и срочности текста.
3. **Защита от дублей:** Сохранение состояния в `logs/cache/poller_last_seen.json` гарантирует, что агент не получит повторных алертов на уже обработанное сообщение.
4. **Асинхронный форвардинг в OpenClaw:** При обнаружении неотвеченного сообщения от клиента формирует промпт с маркерами и передает его в `OPENCLAW_GATEWAY_URL`.

---

### Система маркеров для ИИ-агента

Чтобы LLM-агенту (DeepSeek V4.1 Flash) было предельно просто понять контекст диалога с первого взгляда, поллер размечает сообщение следующими маркерами:

| Маркер | Значение | Рекомендуемое действие ИИ-агента |
| :--- | :--- | :--- |
| `[MARKER: UNANSWERED_CLIENT]` | Клиент ожидает ответа; ни бот, ни оператор еще не ответили. | **Требуется ответ:** сформировать ответ и отправить через `b24_chat_action`. |
| `[MARKER: BOT_REPLIED]` | Бот уже отправил ответ ранее; новых сообщений от клиента нет. | **Ожидание:** не дублировать ответ, ожидать реплики клиента. |
| `[MARKER: OPERATOR_ACTIVE]` | В диалоге работает живой оператор или сотрудник компании. | **Невмешательство:** не перебивать оператора-человека. |
| `[STATUS: NEED_REPLY]` | Диалог находится в состоянии, требующем реакции поддержки. | Обработать вопрос клиента. |
| `[STATUS: WAITING_CLIENT]` | Диалог ожидает ответа от клиента. | Не требует активных действий. |
| `[STATUS: OPERATOR_HANDLED]` | Диалог передан/обрабатывается оператором. | Контроль или помощь внутренней сводкой при запросе. |
| `[PRIORITY: URGENT]` | Обнаружены ключевые слова срочности (*срочно, ошибка, не работает, жалоба, возврат, претензия*) либо ожидание > 10 минут. | **Высший приоритет:** обработать в первую очередь. |
| `[PRIORITY: NORMAL]` | Обычный вопрос или обращение. | Стандартная очередь обработки. |
| `[WAITING_TIME: ...]` | Время с момента последнего сообщения клиента (например, *4 мин. назад*). | Контроль соблюдения SLA ответа. |
| `[LAST_SPEAKER: CLIENT/OPERATOR/BOT]` | Кто был автором последнего сообщения. | Понимание очередности реплик в диалоге. |

Пример сформированного промпта, поступающего агенту:
```text
🚨 [ОТКРЫТАЯ ЛИНИЯ: ТРЕБУЕТСЯ ОТВЕТ ИИ-АГЕНТА]
🔥 [PRIORITY: URGENT] (Внимание: обнаружен триггер срочности или долгое ожидание)
[MARKER: UNANSWERED_CLIENT]
[STATUS: NEED_REPLY]
[LAST_SPEAKER: CLIENT]
[DIALOG_ID: chat123] (для b24_chat_action)
[CHAT_ID: 123]
[UNREAD_MESSAGES: 2]
[WAITING_TIME: 3 мин. назад]
[CLIENT: Иван Петров (ID: 45)]
[CRM_BINDINGS: {"leadId":0,"companyId":10,"contactId":45,"dealId":12}]
[URGENT_TRIGGER_KEYWORD: 'срочно']
---
[ПОСЛЕДНЕЕ СООБЩЕНИЕ ДИАЛОГА]:
Здравствуйте! Срочно нужен акт сверки по договору 12.
```

### Настройка запуска по Cron (Ubuntu Server)

Для автоматического мониторинга добавьте задачу в планировщик `crontab -e` (запуск каждую минуту):

```bash
* * * * * php /var/www/html/poll_openlines.php --forward >> /var/www/html/logs/cron_poller.log 2>&1
```

### Параметры запуска в CLI:
* `--forward` (или `-f`) — автоматически отправлять новые неотвеченные сообщения клиентов в OpenClaw Gateway.
* `--limit=N` (или `-l`) — число проверяемых диалогов (по умолчанию `30`).
* `--all` (или `-a`) — опрашивать все типы чатов, а не только Открытые линии.
* `--force` — принудительный опрос без учета кеша ранее просмотренных сообщений.
* `--json` (или `-j`) — вывод данных в формате JSON.
* `--line=N` — опрашивать только диалоги конкретной Открытой линии (ID линии из `imopenlines.config.list.get`, например `--line=24`).

### Запуск через автоматизацию OpenClaw (HTTP GET/POST)

Скрипт также поддерживает вызов через HTTP-запросы из сценариев автоматизации OpenClaw:

```bash
curl -X GET "https://b24-mcp.your-domain.com/poll_openlines.php?forward=1&line=24&token=ВАШ_MCP_HTTP_AUTH_TOKEN"
```

### Фильтр по конкретной Открытой линии

Если агент должен обслуживать только одну линию, передайте её ID через `--line=N` (CLI) или `line=N` (HTTP).
ID линии виден в `imopenlines.config.list.get` (поле `ID`), а в `im.recent.get` она соответствует
второму сегменту `chat.entity_id` (формат `connector|<LINE_ID>|...`), например
`telegrambot|24|1642658562|1644` — это линия `24` («ТЕСТ AI АГЕНТА ЧАТ С КЛИЕНТАМИ»).

## 9. Постановка задач в Битрикс24 по регламенту компании

Инструмент `b24_create_task` и сервис `src/Services/TaskService.php` строго следуют корпоративному регламенту постановки задач из **6 обязательных пунктов**:

### 📋 Пункты регламента

1. **Название задачи:**
   * Состоит строго из 3-х частей: **`<Группа проектов> | <Смысл задачи> <Дата постановки DD.MM.YYYY>`**.
   * *Пример:* `HR | Заполнить документы по кандидату Андрей Высоцкий 18.02.2025`.
   * *Автоматизация:* Агент может передать либо готовый `title`, либо раздельно `project_group_name` и `task_summary` (дата подставится автоматически в формате текущего дня, если не передана `task_date`).

2. **Описание задачи:**
   * Обязательно должно содержать **краткий план по выполнению данной задачи** (`plan_steps`) и/или **ссылки на регламенты и алгоритмы** (`links`).
   * Сервер отклоняет создание задачи с ошибкой `missing_description_or_plan`, если тело задачи и план пустые.

3. **Участники задачи:**
   * `responsible_id` — ID ответственного исполнителя (обязательно).
   * `accomplices` — массив ID соисполнителей (`[12, 34]`).
   * `auditors` — массив ID наблюдателей (`[56]`).
   * `created_by` — постановщик (по умолчанию автор вебхука).

4. **Крайний срок выполнения (`deadline`):**
   * Обязателен для всех рабочих задач в формате `YYYY-MM-DD HH:MM:SS` или ISO 8601.
   * Бессрочными могут быть исключительно задачи-справочники / мануалы (для них необходимо явно передать флаг `is_manual: true`).

5. **Проектная группа (`group_id`):**
   * Выбор проектной группы строго обязателен!
   * Если ID группы не известен, агент может:
     - Вызвать инструмент `b24_get_workgroups` для поиска группы по названию (`search_query`).
     - Передать параметр `project_group_name` (сервер выполнит автопоиск по активным группам).

6. **Учет времени и предварительные трудозатраты:**
   * Чекбокс **«Учет времени»** выставляется автоматически (`ALLOW_TIME_TRACKING = 'Y'`).
   * Обязательно указание предварительных временных трудозатрат:
     - `time_estimate_hours` — в часах (например, `1.5`).
     - `time_estimate_minutes` — в минутах (например, `90`).
     - Сервер автоматически пересчитывает значение в секунды (`TIME_ESTIMATE = 5400`) для API Битрикс24.

### 📋 Добавление чек-листа в задачу (`b24_add_task_checklist`)

Позволяет пакетно добавить пункты чек-листа в существующую задачу за один запрос `CRest::callBatch`:

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "b24_add_task_checklist",
    "arguments": {
      "task_id": 12345,
      "items": [
        "Собрать скан-копии паспорта и СНИЛС",
        "Подготовить трудовой договор по типовому шаблону",
        "Передать на подпись руководителю отдела"
      ]
    }
  }
}
```

> **Примечание по REST API:** Методы `task.checklistitem.*` требуют строго позиционный массив параметров:
> `[$taskId, ['TITLE' => $title, 'IS_COMPLETE' => 'N', 'SORT_INDEX' => $sort]]`
