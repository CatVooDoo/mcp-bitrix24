# Google CLI для помощника Bitrix24

## Текущая установка: Antigravity (`agy`)

На этом Mac уже установлен и авторизован `agy`. Повторный вход не нужен:

```bash
B24_AGENT_PROVIDER=agy php bin/test-agent.php
```

`B24_AGY_BIN` задаёт путь к бинарнику (по умолчанию `agy` из PATH),
`B24_AGY_MODEL` — доступную модель, иначе сохраняется выбор пользователя.
`B24_AGY_EFFORT` по умолчанию `low`, чтобы ограничить лишнее рассуждение.
Явно выбранный пресет модели должен совпадать с effort: например,
`gemini-3.8-flash-low` + `low`. Конфликт пресета и effort отклоняется до запуска CLI.
Адаптер создаёт отдельный профиль `b24-planner` в `var/agy-planner/`,
с единственным инструментом `finish` для возврата JSON и без skills, plugins и MCP. Настройки
пользователя и авторизация остаются в его профиле; `--settings` применяется
только к вызову помощника. Вывод плана ограничен JSON Schema; результат читается из `structured_output`,
либо из завершённого JSON в `response` с обязательной серверной проверкой той же схемы.
Частичный результат при `finished_reason=print_timeout` отклоняется, даже
если сам CLI пометил его `SUCCESS`.
Передача контекста — через stdin (один stream-json event), новый процесс
для каждого события. Продолжения чужих разговоров нет.

Первый синтетический вызов обычного agy использовал 23 406 входных токенов,
вызов с отдельным профилем — 5 701. Это замеры конкретных запросов, а не
обещание фиксированного расхода: реальный контекст CRM добавит токены.
Usage сохраняется в `agent.log`. Квоты аккаунта продолжают действовать.

Для локального worker вместо `B24_AGENT_PROVIDER=gemini` в примерах ниже
использовать `B24_AGENT_PROVIDER=agy`. Живой тест пока не включён.

## Отдельный пакет Gemini CLI (не требуется для agy)

### Правила и эскалация в задачу

`SUPPORT_AGENT_RULES.md` передаётся агенту как доверенные правила владельца.
Из каталогов передаются компания и проекты, соответствующие текущему обращению.
Для `escalation_channel=task` сервер запрещает `ask_employee`; также отключена
возможность `chat.send_internal`. Схема agy исключает личные вопросы сотрудникам.
Действие `task` создаёт задачу или дополняет уже связанную, фиксирует ожидание
ответа ответственного и плановый срок. Недостающие параметры первичного разбора
заполняются сервером: оценка 15 минут относится к разбору, не реализации работ.
Постановщик и наблюдатели принудительно задаются политикой в TaskService.
Клиент получает фактический номер только после успешного результата Bitrix24.
Комментарии менеджера поднимают исходное обращение; при неполном ответе агент
добавляет уточнение в задачу. Напоминания также идут в комментарии задачи.

### Docker MariaDB + agy на Mac

Для локального запуска с текущей авторизацией agy:

```bash
# Из корня проекта: MariaDB доступна только через loopback Mac.
docker compose -f docker-compose.yaml -f docker-compose.local.yaml up -d mariadb
python3 src/bin/local-worker.py check
python3 src/bin/local-worker.py prime
# Подставить выбранный ID из agy models, например gemini-3.8-flash-high.
python3 src/bin/local-worker.py start --model MODEL_ID --effort high --poll-interval 5 --send
python3 src/bin/local-worker.py status
python3 src/bin/local-worker.py stop
```

`prime` фиксирует начальную границу истории при пустом курсоре. Он не отправляет
сообщений. `start` создаёт два фоновых процесса на Mac: monitor опрашивает чаты и задачи,
worker вызывает agy и выполняет действия. Они используют
ту же MariaDB, что контейнеры. Секреты читаются из конфигурации Compose и
передаются окружением, не через аргументы команды. `--send` явно включает
отправку; без него действия становятся черновиками. Локальные worker и monitor
контролируются PID-файлами; для изменения модели надо сначала остановить его.
Автозапуск после перезагрузки Mac этим скриптом не настраивается. Лог:
`src/var/logs/local-worker.log`. Профиль отслеживаемых чатов — `config/portal.json`.

### Установка отдельного Gemini CLI

Gemini возвращает JSON-план. CRM, задачи, отправку и ожидание обрабатывает PHP worker.
MCP, расширения, инструменты CLI, skills и hooks отключены для этого запуска.
В CLI отправляются последние 6 сообщений и ограниченный контекст; сокращённые поля
помечаются `[TRUNCATED]`. Не хватает данных — уточнение сотруднику, а не догадка.
Статистика CLI и размер контекста пишутся в приватный лог `agent.log`.

## Установка и вход

Команды выполнять из `src/` под тем же пользователем, который запускает worker:

```bash
npm install --prefix var/tools --no-audit --no-fund @google/gemini-cli@0.67.0
var/tools/node_modules/.bin/gemini
```

В интерактивном CLI выбрать **Sign in with Google** и войти аккаунтом с доступом.
Авторизация требует участия пользователя. Копировать токены в исходники не нужно.
Каталог `var/` исключён из Git. CLI можно установить отдельно и указать абсолютный
путь в `B24_GEMINI_BIN`. В Docker CLI и авторизация должны быть доступны именно
внутри контейнера worker; установленного на Mac CLI для контейнера недостаточно.

## Проверка без обращений к Bitrix24

```bash
B24_AGENT_PROVIDER=gemini php bin/test-agent.php
php tests/run.php
python3 tests/http_test.py
```

`test-agent.php` отправляет модели только синтетическое сообщение, не читает CRM,
не забирает события и не отправляет сообщения. Успех: JSON с `success: true`
и непустым действием `reply`. Это проверка интеграции, а не качества поддержки.
Тесты `run.php` используют подставной CLI, настоящую модель вызывает только
`test-agent.php`. Формат CLI: внешний JSON с `response`, внутри — JSON `actions`.

## Включение обработки

Сначала проверить профиль `config/portal.json`, каналы, авторов и права доступа.
При локальном CLI переменные `.env` автоматически не загружаются: их нужно
передать окружением процесса. Docker Compose передаёт корневой `.env` сам.

```bash
export B24_AGENT_PROVIDER=gemini
export B24_AUTOMATION_ENABLED=true
export B24_SEND_ENABLED=false
php bin/console.php doctor --probe
php bin/console.php worker --once
```

При `B24_SEND_ENABLED=false` действия становятся черновиками; автоматической
отправки после переключения флага у них нет. Для согласованного теста в чате:

```bash
export B24_SEND_ENABLED=true
php bin/console.php worker
```

При `initial_history=new` первая сверка только запоминает границу истории.
Тестовое сообщение надо писать после первого прохода monitor.
Сообщения оператора переводят обращение в `HUMAN_OWNED`; такой диалог требует
явного `b24_resume_case` перед продолжением автоматизации.
Неопределённая доставка (`delivery_unknown`) не повторяется автоматически.
Квоты и ошибки авторизации CLI могут задержать обработку; событие остаётся в БД.
Таймаут вызова — 120 секунд, аренда события — 180 секунд.

Опционально `B24_GEMINI_MODEL` выбирает доступную вашему аккаунту модель.
Без этой переменной используется выбор модели в CLI. Локальная установка CLI
подхватывается автоматически; `B24_GEMINI_BIN` имеет приоритет.

Официальные справки: [headless](https://geminicli.com/docs/cli/headless/),
[авторизация](https://geminicli.com/docs/get-started/authentication/).
